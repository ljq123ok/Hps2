# 为什么"我的 BIOS 都能启动，别人不行"

**问题来源**：用户观察到自己的 BIOS 全部能启动，而其他使用者失败。

**结论：目前**无法**给出确切答案 —— 缺少"别人失败"的具体现象与日志。**
本文只列出**已核实的可能原因**，并给出区分方法。

---

## 1. 最可能的原因：不是 BIOS 问题，而是 JIT 门禁

本项目有一个**硬门禁**：JIT 不可用时**拒绝启动**（刻意不做降级）。

```typescript
// Index.ets startBoot()
if (this.jitChecked && !this.jitAvailable) {
  this.statusError = `JIT 不可用，已拒绝启动。${...}`;
  return;   // 直接返回，连 startBios 都不调用
}
```

而 JIT 可用性是**运行期属性**，会自行失效（本项目多次实测，
见 `docs/jit-regression.md`、`docs/jit-failure-correction.md`）：

- 同一台设备、同一 HAP，隔一段时间就可能从"可用"变成不可用
- 恢复手段是**重启设备**（已两次实测有效）

**推论**：别人遇到"启动不了"，很可能看到的是
**"JIT 不可用，已拒绝启动"**，而不是 BIOS 有问题。
用户容易把它描述成"BIOS 启动不了"，因为界面上 BIOS 是启动的前提。

### 区分方法
看界面/日志里是否有：
- `JIT 不可用，已拒绝启动` → JIT 问题，**重启设备**后再试
- `核心启动被拒绝` 或 `BOOT_ERROR=...` → 才是真正进入核心后的失败

## 2. 次可能：BIOS 文件本身

我们**没有做** BIOS 有效性校验（已 grep 确认代码中无 4MB / 有效性检查）。
校验完全由核心（PCSX2）进行。

而文件选择器只按**后缀名**过滤：

```typescript
['.bin', '.BIN', '.rom', '.ROM', '.p2b']
```

**后果**：用户能选中任何 `.bin`/`.rom` 文件 —— 包括：
- 其它机种的 BIOS（如 PSP、PS1 的 bin）
- 损坏或不完整的下载
- 只有部分文件（PS2 BIOS 通常是 4MB / 2MB / 8MB 的特定版本集合）

这些都能被选中，但核心无法据其启动。

### 可改进点（尚未做）
在选择后做一次基本校验并给出明确提示，例如：
- 大小是否为 4MB / 2MB / 8MB 等已知规格
- 是否含 PS2 BIOS 特征串（如 `Sony Computer Entertainment`）

**注意**：这类校验只能排除明显无效的文件，
不能证明"这是合法且完整的 BIOS" —— 措辞需谨慎，避免误导。

## 3. 其它已核实的启动前提

| 前提 | 不满足时的表现 |
|---|---|
| 必须先选 BIOS | 报"请先选择 BIOS 文件" |
| BIOS 需复制进沙箱 | 复制失败会报错（曾因我改错路径而报 13900002）|
| JIT 必须可用 | 报"JIT 不可用，已拒绝启动" |
| 设备需 arm64 + HarmonyOS | 非目标机型无法安装 |

## 4. 为得到确切答案，需要的信息

**目前缺的是"别人失败"的第一手证据。** 若能提供以下任一项，
即可定位：

1. **界面上的完整错误文字**（我们所有失败都会在首页显示 error 卡片）
2. **日志**：`hilog | grep HPS2_CORE`（会显示 `BOOT_ERROR=...` 或
   `JIT_SELFCHECK=...`）
3. **失败时的现象**：卡在黑屏？直接闪退？显示错误后停住？
4. **设备型号与 HarmonyOS 版本**（JIT 行为与系统版本/机型相关）

## 5. 建议的下一步（不依赖用户反馈也能做）

**给失败路径补上更明确的提示与自检**，让用户自己就能区分：

- [ ] 启动失败时，把错误分类显示（JIT 类 / BIOS 类 / 内存类 / 其它）
- [ ] 选完 BIOS 后做一次**基本规格检查**（大小 + 特征串），
      不通过时明确提示"这可能不是有效的 PS2 BIOS"
- [ ] 失败时提供"复制日志"按钮，方便用户发给我们
      （这也是本项目一直缺少的反馈通道）

这三项都能显著降低"用户不知道怎么办"的比例。
