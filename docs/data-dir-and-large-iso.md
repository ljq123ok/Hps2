# 大文件加载问题 与 数据目录外置

来源：外部测试者反馈（2026-09-21）

> 「我把该拥有的 bios 都放完了，我试着点读取相应的 ISO 文件不仅没有进入模拟，
> 还会让应用 GUI 卡了八秒后出现应用闪退，另一个游戏的 bin 文件就能正常加载，
> 我希望你尽快修复这类问题」
>
> 「另外，最好不要忘记更新时将诸如 bios、游戏包括各种日志、存档都改在
> download 文件专门放一个文件作为外置数据保存」

---

## 1. 问题分解

反馈里其实是**两个现象**，必须分开处理（不能当成一个 bug）：

| 现象 | 可能的成因 |
|---|---|
| GUI 卡约 8 秒 | 复制 2-4GB 文件时**同步阻塞 UI 线程** |
| 之后闪退 | 需真机复现定位（复制被系统杀？启动后 CDVD 解析崩？）|

### 1.1 卡顿的成因（已确认，代码层面）

`pickAndCopy()`（`Index.ets:342`）用的是：

```typescript
fs.copyFileSync(srcFile.fd, dstFile.fd);   // 同步复制，且在 UI 线程
```

ISO 动辄 2-4GB。自测 2.24GB 约 2.4 秒；用户文件更大或存储更慢时，
8 秒完全合理。**期间整个 UI 冻结** —— 与用户描述一致。

### 1.2 闪退的成因（待真机复现）

暂不臆测。可能方向：
- 长时间同步 IO 触发系统看门狗 / 超时
- 复制过程中内存或 fd 相关限制
- 复制成功后启动，CDVD 层解析该 ISO 时崩溃

**必须先复现再改**，否则改了也不知道有没有修好。

---

## 2. 用户建议 2 与问题 1 的关系（重要）

用户的建议「数据改在 download 专门放一个文件夹」，
**恰好也能解决卡顿**：

> 若游戏镜像**原地读取**（不复制），就没有 8 秒冻结，
> 也没有 2-4GB 的沙箱冗余占用。

### 2.1 技术前提已核实 ✅

「原地读取」需要能**长期持有**用户授权文件的 URI 读权限
（否则重启后路径失效）。HarmonyOS 提供：

```typescript
fileshare.persistPermission(policies: Array<PolicyInfo>): Promise<void>
```

**权限要求**：`ohos.permission.FILE_ACCESS_PERSIST`

从 SDK 的 `PermissionDefinitions.json` 读到的定义：

```
name              : ohos.permission.FILE_ACCESS_PERSIST
grantMode         : system_grant      ← 系统自动授予，无需用户确认
availableLevel    : normal            ← 非受限权限，不需要 ACL
provisionEnable   : true
since             : 11                （设备为 API 26，满足）
```

**结论**：该权限是 `normal` 级 + `system_grant`，
**不需要 ACL、不需要用户弹窗** —— 符合本项目「不申请受限权限」的约束。
因此「原地读取」方案**技术可行**。

---

## 3. 方案

### 3.1 游戏镜像：原地读取，不复制

```
用户选择 ISO
  → fileshare.persistPermission()  持久化读权限
  → 记录 URI 到应用配置（下次启动直接可用）
  → 直接以该 URI 路径打开，不复制
```

**收益**：
- 消除 8 秒卡顿（不再复制）
- 省下 2-4GB 沙箱空间
- 用户升级/重装应用时游戏不丢（在用户自己的目录里）

**代价**：
- 需要处理"用户删除了文件"的情况（打开失败时给出明确提示）
- BIOS 是否也这样处理？BIOS 只有 4MB，复制无感，但**统一行为更简单**

### 3.2 数据目录外置（用户的建议 2）

把 BIOS / 游戏 / 日志 / 存档都放到用户可见目录，例如：

```
Download/Hps2/
  bios/          用户放入 BIOS
  games/         用户放入游戏镜像
  logs/          emulog.txt 等
  saves/         记忆卡、存档状态
```

**但这里有个技术约束必须先核实**：
应用**无法任意读写**用户目录 —— 需要用户通过选择器授权。
要做到"用户直接往 Download/Hps2 丢文件，应用就能看到"，
需要核实 HarmonyOS 是否允许应用**扫描/读取指定公共目录**，
以及是否属于受限能力。

（如果只能逐个文件授权，那"文件夹"体验就打折扣，
  需要权衡后决定做到什么程度。）

### 3.3 无论选哪条，卡顿都要先修

即使暂时保留复制逻辑，也必须**把复制移出 UI 线程**
（改用异步 API 或 taskpool），否则界面仍会冻结。

---

## 4. 待办与顺序

1. **先真机复现闪退** —— 用 2-4GB 的 ISO 走一遍，抓日志定位
2. 修卡顿（复制异步化，或改原地读取）
3. 核实公共目录读取的技术前提，再决定数据目录方案
4. 更新到真机验证

**顺序理由**：闪退是"不能用"，卡顿是"难用"；且闪退成因未明，
先复现才能对症。
